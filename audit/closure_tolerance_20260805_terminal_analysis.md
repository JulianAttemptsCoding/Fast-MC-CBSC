# Closure tolerance — declared threshold change, 2026-08-05

## Disposition

`QA PASS` for the change itself. **This is a declared threshold change, made on
the project owner's explicit delegation** after the options and their costs were
put to them. Option **A** (scale-aware tolerance) was chosen.

**Anything compared across this change is a new declared experiment.**

## Why a workaround was not available

The p10 analysis listed option **C** — change nothing, add automatic resume — as
a way to keep the threshold pristine and pay in wall-clock. **That option does
not work**, and this is the finding that forced the decision:

- the trainer restores RNG state from the checkpoint, and the visual bank is a
  fixed 50×5 selection with per-position seeds, so resuming from `best.pt`
  re-runs the identical epochs and re-hits the identical failure — a loop;
- resuming from the failing `last.pt` is forbidden outright, because it is an
  artifact quarantined by an invariant failure.

So a 20-epoch run had roughly a coin-flip chance of dying with no legitimate
recovery path.

## What was wrong

`closure_tolerance_gev` is absolute. The two quantities it bounds —
`layer_closure_max_gev` and `event_closure_max_gev` — are the residuals of
float32 reductions over thousands of cells, so they are a few units in the last
place of the magnitude being summed and grow with it.

At 300 GeV, inside the training range, one float32 ULP is 3.05e-5 GeV and
already exceeds the entire 2e-5 GeV tolerance.

## The measurement

100 per-position rows, from
`_diag/dicos-p10/viz_invariants_epoch_0040.json` and
`_diag/dicos-p10/viz_invariants_epoch_0039_control.json`:

| statistic | residual / ULP(total_response) | residual / total_response |
|---|---:|---:|
| max | 7.00 | 8.052e-07 |
| p99 | 7.00 | — |
| p95 | 5.00 | 4.071e-07 |
| median | 1.00 | 8.377e-08 |

Response range 1.0692 – 36.9113 GeV. The residual is ULP-quantized: bounded and
small in ULP, varying 100× in absolute terms. That is the whole diagnosis,
measured rather than argued.

## The change

```text
bound = max(closure_tolerance_gev, closure_tolerance_relative * total_response)

closure_tolerance_gev       2e-5    unchanged, still binds below 2 GeV
closure_tolerance_relative  1e-5    new; DEFAULTS TO 0.0
```

The default is load-bearing. A config frozen before 2026-08-05 carries no such
key, so it keeps the exact absolute-only rule and its accepted runs stay
reproducible. Only configs generated by `scripts/build_final_continuation.py`
from 2026-08-05 declare the relative term.

## Why 1e-5

- **12× above** the largest measured float32 residual (8.052e-07 relative);
- **~2 orders of magnitude below** the residual a single mis-decoded cell would
  produce — a dropped cell shifts a layer budget by of order the cell energy,
  ~0.05 GeV at 33 GeV, which is 1.5e-3 relative;
- the crossover with the absolute floor is exactly `2e-5 / 1e-5` = **2 GeV**, so
  low-energy events keep the old, stricter rule unchanged.

It admits float32 noise without admitting a defect, and there is a ~150× gap
between the two regimes, so the choice is not delicate.

## Empirical validation

Replaying all 100 measured rows under the new rule:

```text
fail under OLD rule    1     <- the row that ended dicos-p10
fail under NEW rule    0
tightest row: residual 2.670288e-05, tolerance 3.316457e-04, response 33.1646 GeV

structural fields across all 100 rows: every one exactly 0
```

## One defect found and fixed during implementation

The first implementation used `max(absolute, relative * scale)` unconditionally.
With `relative = 0.0` that silently raises a deliberately **negative** tolerance
to `0.0`. `tests/test_epoch_visualization.py` forces an invariant failure by
setting `closure_tolerance_gev = -1.0`, so an exact-zero residual began passing
and that test started reporting `DID NOT RAISE`. The relative branch now
participates only when `relative > 0.0`, and
`test_a_deliberately_negative_tolerance_is_not_raised_to_zero` pins it.

This is exactly the failure mode `AGENTS.md` 23 exists to catch: a change that
made a guard stop guarding. It was caught by the suite, not by inspection.

## Scope of the code change

```text
src/cbsc_zdc/eval/invariants.py     relative term + closure_tolerances() reader
src/cbsc_zdc/training/trainer.py    _checkpoint_invariant_gate, 7 draws/epoch
src/cbsc_zdc/eval/visualization.py  export_epoch_visualization, 250 draws/epoch
src/cbsc_zdc/eval/evaluator.py      evaluation invariants
src/cbsc_zdc/cloud/vertex_stage.py  smoke and postflight gates
scripts/build_final_continuation.py declares the term in generated configs
tests/test_closure_tolerance.py     8 new contracts
```

One reader, `closure_tolerances(config)`, serves all five gates so they cannot
drift apart. Every term is written into each report so a verdict can be
recomputed from the record without re-running the generator.

`AGENTS.md` gains rule **28**: a threshold is not a free parameter in either
direction, and a threshold must be able to express the quantity it bounds.

## Boundary

data, the split, the seed, or any selection rule. It establishes nothing about
Geant4 fidelity. `PHYSICS VALIDATION NOT ESTABLISHED`.

old rule and re-auditing it under the new one is a separate declared act that has
